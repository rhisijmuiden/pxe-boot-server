Getting started

  1. Open Network & PXE, tick the network interface(s) clients are on and choose Proxy DHCP. Your router keeps handing out IP addresses; this server only adds the boot information.
  2. Upload ISO files in the ISO library. Each ISO is mounted and detected automatically, and appears in the boot menu.
  3. On the client, turn off Secure Boot and start from the network (often F12, F11 or Esc during start-up). Choose the ISO in the menu.

How booting works

  1. The client's firmware sends a PXE request. dnsmasq on this server answers with a boot file: undionly.kpxe for Legacy BIOS or {{ uefi }} for UEFI, served over TFTP.
  2. That file is iPXE with a small built-in script. iPXE asks DHCP again and loads http://<this server>/ipxe/boot.ipxe.
  3. The menu is generated from the ISO library. Folders become submenus. A machine you linked to an ISO skips the menu.
  4. The chosen ISO boots with the method that fits it:
    • Windows: wimboot loads boot.wim. Setup then reads the rest of the ISO from the Windows share \\{{ server_ip }}\pxe (TCP 445).
    • Ubuntu, Debian, Rocky/Alma/Fedora, Arch, Proxmox: the kernel and initrd come from the mounted ISO over HTTP, with the right options to find the rest of the installer.
    • Everything else: sanboot attaches the ISO as a virtual CD-ROM over HTTP. This works for many tools (memtest, firmware updaters). An operating system that needs the CD after its own kernel has started may not find it; then try memdisk (Legacy BIOS only) via the menu in the library.

Using the PXE server across VLANs with a UniFi UDM-Pro

PXE starts with a broadcast that does not cross VLANs. There are three ways to reach clients on other networks. Option A is the most complete: it supports Legacy BIOS and UEFI on every VLAN and needs no firewall changes.

Option A (recommended): give the server a leg in every VLAN

  1. In UniFi Network, open Ports on the switch the PXE server is connected to (UniFi Devices > your switch > Port Manager) and set that port to carry the VLANs you want as tagged networks, with the server's main network as native. In recent versions this is "Native VLAN / Network" plus "Tagged VLAN Management: Allow All" or a custom list.
  2. Here, in Network & PXE, use Add VLAN interface: pick the physical interface, enter the VLAN ID and a free static address in that VLAN (for example 10.0.50.5/24). Reserve that address in UniFi or keep it outside the DHCP range.
  3. Tick the new interface (for example eth0.50) and click Apply. dnsmasq now answers PXE requests in that VLAN as proxy DHCP. The UDM-Pro keeps handing out addresses.

Clients talk to the server's address in their own VLAN, so traffic is not routed through the UDM-Pro and no firewall rules are needed.

Option B: UniFi Network Boot (DHCP option 66/67)

  1. In UniFi Network go to Settings > Networks, open the client network, and under DHCP enable Network Boot (in some versions under "Advanced" or "DHCP Service Management").
  2. Server: {{ server_ip }}. Filename: {{ uefi }} for UEFI clients, or undionly.kpxe for Legacy BIOS clients.
  3. Add the firewall rules below so the network can reach this server.

UniFi sends one file name to every client on that network, so a network uses either UEFI or Legacy BIOS. Most current hardware is UEFI. Our iPXE files include a script that reads the boot server from next-server, so there is no chainload loop.

Option C: a dedicated install VLAN with DHCP relay

  1. Create a network such as "Install" in UniFi and set its DHCP Mode to DHCP Relay, pointing at {{ server_ip }}.
  2. Here, choose Full DHCP server and enter a range in the install network (for example 10.0.60.100 - 10.0.60.200), the UDM-Pro as gateway and your DNS servers.
  3. Add the firewall rules below. Machines are moved to this VLAN (switch port profile) while they are installed.

Both Legacy BIOS and UEFI work, because this server picks the boot file per client.

Firewall rules for options B and C

With the zone-based firewall of UniFi Network 9 and later, traffic between networks in the Internal zone is allowed by default. If you put networks in separate zones or turned on network isolation, add an Allow policy from the client network to this server ({{ server_ip }}), with return traffic allowed:

Windows

  • Turn off Secure Boot: iPXE and wimboot are not signed by Microsoft.
  • Setup runs from the network share. If setup cannot find a disk, the ISO has no driver for the storage controller (common with Intel VMD/RST). Turn VMD off in the BIOS or add drivers to boot.wim.
  • Windows 11 checks TPM 2.0 and Secure Boot capability, not whether Secure Boot is switched on.
  • Both Legacy BIOS and UEFI work with the same ISO.

Linux and answer files

  • Ubuntu downloads the whole ISO into memory during boot, so the client needs RAM of at least the ISO size plus 1 GB.
  • Debian netinst and DVD boot the matching Debian network installer, which installs packages from a Debian mirror. This server downloads that installer once per release.
  • Proxmox VE loads the whole ISO into memory (about 1.5 GB). For an unattended install, this server makes a copy of the ISO that fetches its answer file over HTTP; that copy is built when you save the answer file.
  • Answer files turn an install into a hands-off one. Link a machine's MAC address to an ISO and answer file in Machines with "Next boot only", and the machine installs once and then gets the normal menu again.

Troubleshooting

  • No PXE answer at all: check that the right interface is ticked in Network & PXE and that dnsmasq is running on the dashboard. On another VLAN, see the options above.
  • "No boot server found": the DHCP answer contained neither proxy DHCP nor next-server. With option B, check the Network Boot server address.
  • Menu loads but an ISO fails: open the ISO's menu in the library and choose another boot method, then try again.
  • Client shows the menu but you want local disk: set the default entry to "Boot from local disk" in Boot menu; it is used after the timeout.
  • Keyboard does not work in the UEFI boot menu: use snponly.efi as UEFI loader in Network & PXE (the default). ipxe.efi brings its own drivers and on many PCs the firmware's USB keyboard support stops while it runs. If a client gets no network with snponly.efi, switch to ipxe.efi. Legacy BIOS clients use undionly.kpxe, which keeps the BIOS keyboard.
  • Proxmox VE VM does not boot over the network with UEFI: give the VM an EFI disk in the 2MB OVMF format. In our tests the 4MB format did not boot from the network. Legacy BIOS (SeaBIOS) VMs work as they are.
