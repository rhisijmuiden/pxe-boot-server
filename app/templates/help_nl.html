Aan de slag

  1. Open Netwerk & PXE, vink de netwerkkaart(en) aan waar de clients op zitten en kies Proxy DHCP. Je router blijft IP-adressen uitdelen; deze server voegt alleen de bootinformatie toe.
  2. Upload ISO-bestanden in de ISO-bibliotheek. Elke ISO wordt automatisch gekoppeld en herkend, en komt in het bootmenu.
  3. Zet op de client Secure Boot uit en start via het netwerk (vaak F12, F11 of Esc tijdens het opstarten). Kies de ISO in het menu.

Zo werkt booten

  1. De firmware van de client stuurt een PXE-verzoek. dnsmasq op deze server antwoordt met een bootbestand: undionly.kpxe voor Legacy BIOS of {{ uefi }} voor UEFI, via TFTP.
  2. Dat bestand is iPXE met een klein ingebouwd script. iPXE vraagt opnieuw DHCP aan en laadt http://<deze server>/ipxe/boot.ipxe.
  3. Het menu wordt gemaakt uit de ISO-bibliotheek. Mappen worden submenu's. Een machine die je aan een ISO hebt gekoppeld slaat het menu over.
  4. De gekozen ISO start met de methode die erbij past:
    • Windows: wimboot laadt boot.wim. Setup leest daarna de rest van de ISO via de Windows-share \\{{ server_ip }}\pxe (TCP 445).
    • Ubuntu, Debian, Rocky/Alma/Fedora, Arch, Proxmox: kernel en initrd komen via HTTP uit de gekoppelde ISO, met de juiste opties om de rest van de installatie te vinden.
    • Al het andere: sanboot koppelt de ISO via HTTP als virtuele cd-rom. Dat werkt voor veel tools (memtest, firmware-updates). Een besturingssysteem dat de cd nodig heeft nadat zijn eigen kernel is gestart, vindt hem soms niet; probeer dan memdisk (alleen Legacy BIOS) via het menu in de bibliotheek.

De PXE-server over meerdere VLAN's gebruiken met een UniFi UDM-Pro

PXE begint met een broadcast, en die gaat niet van het ene VLAN naar het andere. Er zijn drie manieren om clients in andere netwerken te bereiken. Optie A is het meest compleet: Legacy BIOS en UEFI werken in elk VLAN en je hoeft niets aan de firewall te doen.

Optie A (aanbevolen): geef de server een poot in elk VLAN

  1. Open in UniFi Network de poortinstellingen van de switch waar de PXE-server op zit (UniFi Devices > je switch > Port Manager) en laat die poort de gewenste VLAN's als tagged netwerken doorgeven, met het hoofdnetwerk van de server als native. In recente versies heet dit "Native VLAN / Network" plus "Tagged VLAN Management: Allow All" of een eigen lijst.
  2. Gebruik hier in Netwerk & PXE de knop VLAN-interface toevoegen: kies de fysieke netwerkkaart, vul het VLAN-ID in en een vrij vast adres in dat VLAN (bijvoorbeeld 10.0.50.5/24). Reserveer dat adres in UniFi of houd het buiten de DHCP-range.
  3. Vink de nieuwe interface aan (bijvoorbeeld eth0.50) en klik op Toepassen. dnsmasq beantwoordt nu PXE-verzoeken in dat VLAN als proxy DHCP. De UDM-Pro blijft adressen uitdelen.

Clients praten met het adres van de server in hun eigen VLAN. Het verkeer gaat dus niet via de UDM-Pro en je hebt geen firewallregels nodig.

Optie B: UniFi Network Boot (DHCP-optie 66/67)

  1. Ga in UniFi Network naar Settings > Networks, open het netwerk van de clients en zet onder DHCP de optie Network Boot aan (in sommige versies onder "Advanced" of "DHCP Service Management").
  2. Server: {{ server_ip }}. Bestandsnaam: {{ uefi }} voor UEFI-clients, of undionly.kpxe voor Legacy BIOS-clients.
  3. Voeg de firewallregels hieronder toe zodat het netwerk deze server kan bereiken.

UniFi geeft elke client in dat netwerk dezelfde bestandsnaam, dus een netwerk gebruikt óf UEFI óf Legacy BIOS. De meeste huidige hardware is UEFI. Onze iPXE-bestanden bevatten een script dat de bootserver uit next-server haalt, dus er ontstaat geen lus.

Optie C: een apart installatie-VLAN met DHCP-relay

  1. Maak in UniFi een netwerk zoals "Install" en zet de DHCP Mode op DHCP Relay, met {{ server_ip }} als server.
  2. Kies hier Volledige DHCP-server en vul een bereik in het installatienetwerk in (bijvoorbeeld 10.0.60.100 - 10.0.60.200), de UDM-Pro als gateway en je DNS-servers.
  3. Voeg de firewallregels hieronder toe. Machines zet je tijdens de installatie in dit VLAN (poortprofiel op de switch).

Legacy BIOS en UEFI werken allebei, omdat deze server per client het juiste bootbestand kiest.

Firewallregels voor optie B en C

Met de zone-gebaseerde firewall van UniFi Network 9 en nieuwer is verkeer tussen netwerken in de zone Internal standaard toegestaan. Heb je netwerken in aparte zones gezet of netwerkisolatie aangezet, maak dan een Allow-policy van het clientnetwerk naar deze server ({{ server_ip }}), met retourverkeer toegestaan:

Windows

  • Zet Secure Boot uit: iPXE en wimboot zijn niet door Microsoft ondertekend.
  • Setup draait vanaf de netwerkshare. Ziet setup geen schijf, dan heeft de ISO geen driver voor de opslagcontroller (vaak bij Intel VMD/RST). Zet VMD uit in de BIOS of voeg drivers toe aan boot.wim.
  • Windows 11 controleert TPM 2.0 en of Secure Boot mogelijk is, niet of het aan staat.
  • Legacy BIOS en UEFI werken allebei met dezelfde ISO.

Linux en antwoordbestanden

  • Ubuntu laadt tijdens het opstarten de hele ISO in het geheugen. De client heeft dus minstens de grootte van de ISO plus 1 GB aan RAM nodig.
  • Debian netinst en dvd starten het bijbehorende Debian-netwerkinstallatieprogramma, dat pakketten van een Debian-mirror haalt. Deze server downloadt dat programma eenmalig per versie.
  • Proxmox VE laadt de hele ISO in het geheugen (ongeveer 1,5 GB). Voor een installatie zonder vragen maakt deze server een kopie van de ISO die zijn antwoordbestand via HTTP ophaalt; die kopie wordt gemaakt als je het antwoordbestand opslaat.
  • Met antwoordbestanden installeer je zonder vragen. Koppel in Machines een MAC-adres aan een ISO en antwoordbestand met "Alleen volgende boot", dan installeert de machine één keer en krijgt hij daarna weer het gewone menu.

Problemen oplossen

  • Helemaal geen PXE-antwoord: controleer of de juiste netwerkkaart is aangevinkt bij Netwerk & PXE en of dnsmasq draait op het dashboard. In een ander VLAN: zie de opties hierboven.
  • "No boot server found": het DHCP-antwoord bevatte geen proxy DHCP en geen next-server. Bij optie B: controleer het serveradres bij Network Boot.
  • Menu laadt, maar een ISO start niet: kies in de bibliotheek via het menu van die ISO een andere bootmethode en probeer opnieuw.
  • Client toont het menu, maar moet van de lokale schijf starten: zet bij Bootmenu de standaardkeuze op "Start vanaf lokale schijf"; die wordt na de wachttijd gebruikt.
  • Toetsenbord werkt niet in het UEFI-bootmenu: gebruik snponly.efi als UEFI-loader bij Netwerk & PXE (de standaard). ipxe.efi heeft eigen drivers, en op veel pc's werkt het USB-toetsenbord van de firmware dan niet meer. Krijgt een client geen netwerk met snponly.efi, kies dan ipxe.efi. Legacy BIOS-clients gebruiken undionly.kpxe, waarmee het BIOS-toetsenbord blijft werken.
  • VM in Proxmox VE start niet via het netwerk met UEFI: geef de VM een EFI-schijf in het 2MB OVMF-formaat. In onze tests startte het 4MB-formaat niet via het netwerk. VM's met Legacy BIOS (SeaBIOS) werken zoals ze zijn.
